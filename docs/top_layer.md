# Top Layer 显示层说明

## 1. 目的

本文件用于记录当前放置在 `top layer`（`lv_layer_top()`）的 UI 组件，并说明其放置原因，方便后续统一维护与扩展。

`top layer` 的使用目标是：

- 让跨页面的浮层组件保持全局可见，不受单个页面容器层级影响。
- 避免页面切换时浮层被遮挡或被页面生命周期（create/hide/destroy）意外销毁。
- 为系统级短时提示/全局控制提供统一承载层。

## 2. 当前 top layer 组件清单

### 2.1 Volume Bar

- 组件：音量条（`volume bar`）
- 实现位置：`src/ui/volume_bar.c`
- 挂载方式：`lv_obj_create(lv_layer_top())`
- 说明：用于全局音量提示。

### 2.2 Top Notice

- 组件：全局提示通知（`top notice`）
- 实现位置：`src/ui/top_notice.c`
- 挂载方式：`lv_obj_create(lv_layer_top())`
- 触发场景：WiFi 连接状态、网络异常、云端超时、模式切换阻塞等跨页面短时提示
- 生命周期策略：在 `ui_main()` 启动时初始化（`top_notice_init()`）；通过通用接口按类型更新文本并显示（`top_notice_show/top_notice_show_for/top_notice_update`）；超时自动隐藏，或通过 `top_notice_hide()` 主动隐藏

Top Notice 放入 `top layer` 的原因：

- 提示是跨页面共享能力，不属于单个页面。
- 页面切换时提示需要保持可见，避免被页面容器销毁或遮挡。
- 统一入口可保证提示风格与时序一致，页面只关心业务语义（信息/警告/错误等）。

Volume Bar 放入 `top layer` 的原因：

- 音量条是跨页面触发的全局浮层，不属于某一个具体页面。
- 音量调节过程中需要始终显示在最上层，避免被当前页面 UI 元素覆盖。
- 音量条有独立显示/隐藏定时逻辑（自动淡出），放在顶层更容易与页面生命周期解耦。

## 3. 后续新增组件约定

后续若有新组件放入 `top layer`，请在本文件追加记录，至少包含：

- 组件名称
- 代码位置
- 触发场景
- 放入 `top layer` 的必要性说明（为何不能放在页面容器内）
- 生命周期策略（何时创建、显示、隐藏、销毁）

建议优先将下列类型组件放入 `top layer`：

- 跨页面共享且需要短时浮现的系统提示
- 必须保证最高显示层级的全局控制组件

不建议放入 `top layer` 的组件：

- 仅在单页面内使用且与页面布局强耦合的普通 UI 控件
